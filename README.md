# Quarry

**Deterministic commerce search with bounded process parallelism.**

Quarry turns natural-language shopping requests into ranked products while keeping price, availability, exclusions, and compatibility under deterministic control. Its engineering question is precise: **can feature computation run across processes without changing the ordered search result or commerce decision?**

![Quarry searching a synthetic catalogue for a misspelled speaker request under ₹5,000](docs/screenshots/search.png)

The workbench runs the actual engine against reproducible fictional catalogues of **1,000, 10,000, or 50,000 products**. Results expose ranking evidence, parsed constraints, eligibility counts, worker PIDs, queue delay, startup cost, and global fusion time. Individual request timings are observations, not benchmark claims.

## Run locally

Requires **Python 3.12**, Git, and a machine with at least two allocated CPUs for the complete test suite. No database, payment credentials, API key, downloaded model, or Node installation is required.

```powershell
git clone https://github.com/ADITHYA-SANJEEVI/quarry.git
cd quarry
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
cd backend
..\.venv\Scripts\python.exe -m app.services.hpc.cli generate --sizes 1000 10000 50000
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 18765
```

Open **http://127.0.0.1:18765**; interactive API documentation is at `/docs`. On macOS/Linux, replace `.venv\Scripts\python.exe` with `.venv/bin/python` and use `/` path separators. The lock records the tested Windows/Python 3.12 dependency set; other platforms have not been certified. Generated JSONL files stay local. Small committed manifests verify the regenerated bytes.

Try `i need a gud speakr under 5000`, `usb c charger under 1000`, or `gentle cleanser and fragrance-free moisturiser under 1500`. Select process workers to inspect actual parallel execution. Unsupported CPU budgets produce an explicit error; automatic mode may fall back to serial execution.

## Why parallel search is difficult

BM25 depends on corpus statistics. Reciprocal rank fusion depends on complete lane orderings. Ranking independently inside shards, pruning local candidates, or changing floating-point accumulation can change the final result. Process startup, snapshot replication, pickling, result transfer, and admission queues can also cost more than the saved compute time.

Quarry builds global query context once, partitions only scalar feature work, validates every returned row, restores canonical ordering, and performs fusion and commerce decisions in the coordinator. It retains the original serial relevance adapter as a reference.

```text
Natural-language request
  → controlled vocabulary, typed roles, budgets, exclusions
  → immutable catalogue snapshot
  → pre-retrieval eligibility gates
  → global corpus/query context
  → serial features OR bounded persistent spawn workers
  → validated rows in canonical document order
  → global BM25 / fuzzy / trigram / phrase lane fusion
  → final eligibility gate
  → commerce ranking, evidence, adequacy, preview decision
```

See [architecture](docs/architecture.md) for execution boundaries, failure semantics, and remaining coordinator costs.

## Retrieval and constraints

The deterministic adapter computes BM25, RapidFuzz similarity, character-trigram similarity, and phrase features. Global reciprocal rank fusion combines retrieval lanes; the commerce ranker adds product-fact evidence and intent-specific signals. This is an in-memory scan over eligible products, not an ANN service or a persistent inverted index.

Hard gates reject inactive, archived, out-of-stock, over-budget, excluded, or incompatible products. Role enforcement uses canonical product facts at the final gate; legacy factless fixtures retain their existing compatibility behavior. Relevance cannot relax eligibility. Multi-role requests can produce an isolated preview assembled by the existing compiler; these previews cannot be purchased.

The release fixes two demonstrated defects: `speaker` was absent from the controlled role vocabulary despite existing catalogue facts, and hard exclusions skipped canonical role facts. Adding the role lets the existing bounded fuzzy normalizer repair `speakr`; extending conflict evaluation makes `speaker without speaker` reject those products. The original typo query returned no recommendations even though its price cap was parsed correctly. Regression tests cover retrieval, budget preservation, impossible budgets, exclusions, and parallel parity. These are bounded repairs, not general conversational-language coverage.

## Worker execution and observability

The runtime supports **1, 2, 4, and 8 spawn processes**, subject to CPU affinity/quota and configured capacity. A bounded semaphore admits pending requests; a FIFO gate serializes feature batches. Snapshot generation and worker count identify a persistent pool. Changes replace that pool rather than mixing generations.

Returned batches carry request, context, partition, generation, process, and document identities. Missing, duplicate, stale, corrupt, and nonfinite results are rejected. Timeout or worker failure discards owned pool resources; a later request can rebuild the pool. Serial fallback requires an explicit policy. This provides local process recovery, not distributed availability.

![A real process-worker search showing admission, startup, feature and fusion observations](docs/screenshots/workers.png)

The retained tracing modules also distinguish measured serialization probes from inferred transport/scheduling residuals. Pickle probes are not executor wire-byte measurements. The first-release workbench presents request metadata; the richer research analysis/quality modules are available as Python APIs and are not a separate hosted dashboard.

## Correctness and reproduction

From the repository root, after catalogue generation:

```powershell
New-Item -ItemType Directory -Force backend/artifacts | Out-Null
.\.venv\Scripts\python.exe -m pytest -q --basetemp=backend/artifacts/pytest-run
.\.venv\Scripts\python.exe -m pip check
```

The suite covers exact scalar feature equality with the reference adapter, complete-result digest parity, worker reuse, immutable snapshots, real worker death and recovery, timeout cleanup, stale/corrupt batch rejection, bounded admission, FIFO scheduling, deterministic catalogue checksums at all three sizes, experiment checkpoints, and the HTTP/application seam. Full-result digests include ordered visible and unbounded rankings, hexadecimal float scores, evidence, adequacy, eligible products, and preview decisions. They establish equality on tested workloads, not universal correctness.

Validation records and exact results are in [release evidence](docs/release-evidence.md). The original payment/authentication golden harness is outside this release; focused engine tests replace its dependencies. [Source provenance](docs/provenance.md) documents these adaptations.

## Performance evidence

Use the retained experiment runner after stopping the web server and other test/benchmark work:

```powershell
cd backend
..\.venv\Scripts\python.exe -m app.services.hpc.cli run --config ../benchmarks/smoke.json
..\.venv\Scripts\python.exe -m app.services.hpc.cli export <run-id> --output ../docs/evidence/smoke-run.json
```

The small configuration compares the original serial adapter with two process workers at 1,000 products, concurrency one, across scoring and full-search scopes. Untimed exact parity preflight is distinct from warmups and timed observations. Failed observations are retained. [The performance report](docs/performance.md) defines the timing scopes, raw evidence, hardware context, and interpretation.

The default matrix is **3 catalogue sizes × 4 worker counts × 3 concurrency levels = 36 configurations**, or **72 cells across two scopes**. This release does not claim a completed full matrix. A previously reported **46% median-latency improvement is unverified** and is not a release result. Parallelism can be slower, especially for narrow queries and small candidate sets.

Experiment administration is disabled until `HPC_ADMIN_TOKEN` is supplied locally. Keep it outside Git and the browser. The workbench uses public synthetic search routes only. Bind this research application to loopback; public multi-user hosting requires additional authentication and resource controls.

```text
backend/app/main.py             isolated FastAPI application

docs/                          architecture, provenance, evidence, screenshots
```

## Provenance, licensing, and limitations

Quarry is the public identity of a reviewed **HPC search subsystem extracted from the Razorpay Buildathon workspace**. The original application was still named Razorpay Buildathon/Studio. This repository begins with a source snapshot including untracked work; it does not publish the original Git history or claim the entire Buildathon application as Quarry.

The parent project implements Razorpay order/payment integration. That integration, its receipts, Supabase authentication, merchant UI, original Next.js frontend, and local databases are excluded from this offline release. Retained order/model schemas support original type and compiler contracts; there are no payment mutation routes. No real payments were made during release verification.

Original source, authored fixtures, synthetic generator, workbench, and documentation are released under [MIT](LICENSE). Dependencies retain their own [licenses](THIRD_PARTY_NOTICES.md). No marketplace/Kaggle dataset, pretrained model, external product photography, or payment screenshot is redistributed. [Provenance and source ownership](docs/provenance.md) and the [publication audit](docs/security.md) record the boundary and checks.

Known limits include a narrow English commerce vocabulary, synthetic product facts, full-scan retrieval, replicated per-process snapshots, coordinator-bound fusion and ranking, serialized feature batches, platform-dependent timings, and unverified production relevance. Optional model/provider adapters remain inherited source and are disabled by default; their downloads, weights, credentials, and quality claims are outside the release. The complete original shopper/merchant experience is not included. See the [screenshot gallery](docs/screenshots/README.md) and [technical limitations](docs/architecture.md#limitations).
